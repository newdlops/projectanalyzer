# 로컬 함수 해설 문맥 조절 명세

이 문서는 로컬 모델 실행의 문맥·메모리 계약을 정의하는 SPEC 보충 문서다.
별도 학습 실험, 가중치 변경과 함수 예시 입력 항목 수 변경은 포함하지 않는다.

이 개선은 0.0.1147 Mac용 VSIX에 포함된다. 아래의 0.0.1146 설치 상태는 최초 검증
당시의 기록이며, 현재 릴리스 검증은 [0.0.1147 기록](RELEASE_PROGRESS_0.0.1147.json)을 따른다.

## 설정과 사용자 동작

- `projectAnalyzer.functionNarratives.localContextTokens`: 기본 32,768, 최소 8,192,
  최대 131,072토큰, 1,024토큰 단위의 문맥 상한. 전체 지시문·원문·응답을 포함한다.
- `projectAnalyzer.functionNarratives.localMemoryReservePercent`: 기본 25, 최소 20,
  최대 30%. 운영체제와 다른 앱을 위해 남길 시스템 메모리 비율이다.
- VS Code 기본 설정 UI의 숫자 입력과 기존 한국어·영어 NLS를 사용한다.
  설정은 분석 시작 때 고정하며 진행 중인 묶음을 다른 설정으로 바꾸지 않는다.
- 정상 분석·진행률·취소·저장 결과의 이어서 분석 동작은 기존 방식을 유지한다.
  메모리 부족, 입력 문맥 초과, 함수 예시 입력 32개 초과를 서로 다른 상태로 안내한다.
  메모리/문맥 실패는 모델 작업 이력에 원문 없는 진단 코드로 남긴다.

VS Code 설정에서 다음 값으로 기본 동작을 명시할 수 있다. `localContextTokens`를
65,536 등으로 늘려도 해당 크기를 미리 할당하지 않고 필요한 요청에서만 사용한다.

```json
{
  "projectAnalyzer.functionNarratives.localContextTokens": 32768,
  "projectAnalyzer.functionNarratives.localMemoryReservePercent": 25
}
```

## 실행 계약

`src/llm/functionNarratives/context`는 순수 선택 정책, OS 메모리 adapter와 공개 타입을
분리한다. 서버와 CLI가 이 경계를 공유한다. 모델 활성화 시 자동 실행하지 않는다.

서버는 먼저 8,192토큰 문맥으로 준비한다. `/apply-template`로 얻은 실제 입력을
`/tokenize`로 세어 응답 2,400토큰과 특수 토큰 여유 256토큰을 함께 확보한다.
필요하면 16K·32K 등 가장 작은 배수 단계로 확장하며, 메모리 여유가 빠듯할 때는
필요한 최소 1,024토큰 단위 크기를 사용한다. 메모리와 문맥에 맞추려고 원문을
잘라내지 않는다. 작은 후속 요청은 이미 준비된 문맥을 재사용한다.

`/v1/models`가 제공하는 `meta.n_ctx_train`이 있으면 설정 상한보다 우선한다.
이 메타데이터가 없는 구형 서버 및 커스텀 CLI에서는 모델 자체의 한도를 실행기가
판정한다. `/tokenize`가 404를 반환하거나 CLI로 실행하는 경우 UTF-8 바이트 수에
여유를 더한 보수적 추정치를 사용하므로 서버의 실제 토큰 수보다 일찍 상한에 닿을 수 있다.
다른 토큰화 오류는 추론을 시작하지 않고 실패로 보고한다.

확장/축소는 같은 FIFO 소유권 안에서 기존 서버와 watchdog의 종료를 기다린 뒤
새 서버를 준비한다. 두 모델을 동시에 보유하지 않는다. 교체 중 취소·시작 실패도
기존 release 계약을 통해 프로세스와 개인 socket/key 파일을 정리한다.

## 메모리 추정과 한계

macOS는 `memory_pressure -Q`의 시스템 여유 비율을 사용하며 관측은 2초로 제한한다.
실패하거나 다른 OS인 경우 Node의 free-memory 관측을 사용한다. 이 값은 OS마다
회수 가능한 cache를 다르게 포함하므로 동일한 실제 사용량을 뜻하지 않는다.

새 로드는 모델 파일 크기 + 실행기 여유 512 MiB + 문맥 토큰당 256 KiB로 추정한다.
준비된 서버의 확장은 기존 문맥을 뺀 추가 토큰만 먼저 계산한다. 교체 시 종료한 뒤
새 로드의 전체 예산을 다시 확인한다. 이는 특정 모델의 실제 RSS/KV cache 측정값이
아니며 보수적인 admission 추정치다. 서버는 로드 직후와 각 생성 직전에도 실제 시스템
여유를 확인한다. CLI는 시작 전 추정만 가능하다. 다른 앱의 동시 할당이나 모델별
메모리 차이 때문에 실행 전체에서 여유 비율을 보장하지는 않는다. 앱을 자동 종료하거나
백그라운드에서 모델을 반복 로드해 실행 시점을 기다리지 않는다.

## 검증 기준

기능 검증은 실제 token budget·설정/모델 상한·메모리 상한·교체 중 취소·단일 프로세스
소유권·설정의 분석별 고정·두 언어의 오류와 재시도/기존 결과 보존을 포함한다.
시각 검증은 기존 Guide의 오류 영역과 재시도 버튼을 한국어·영어와 좁은/넓은 화면에서
확인하며, 기능 테스트만으로 시각 검증을 통과했다고 판단하지 않는다.

서버 API의 근거는 [llama.cpp 서버 문서](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)의
`/apply-template`, `/tokenize`, `/v1/models` 계약이다.

### 2026-10-29 확인 결과

- TypeScript 검사/컴파일과 관련 단위·Host·Webview 테스트 106개 통과.
  실제 소켓/프로세스 경계의 8K→16K 교체, 교체 중 취소, 기존 PID 종료와 키 삭제,
  메모리/모델 한도에서 생성 미시작, CLI의 긴 원문 끝부분 보존을 포함한다.
- 실제 Qwen3.5-4B Q4_K_M에 공개 합성 입력 9,040토큰을 전달했다. 현재 예산에 따라
  문맥 12,288토큰을 선택하고 10토큰의 스키마 일치 응답을 받았다. 종료 후 manager의
  자원 정리가 완료됐다. 이는 문맥 조절 검증이며 함수 해설의 의미 정확도 검증은 아니다.
- 현재 Guide 컴포넌트와 CSS를 실제 Chrome의 iframe viewport 390×844, 768×1024,
  1440×900에서 확인했다. 각각 한국어 메모리 오류, 영어 문맥 오류, 한국어 입력 인자
  제한 상태와 버튼 배치를 확인했고 가로 넘침·스크립트 오류가 없었다. 390px 화면에서
  Enter 재시도도 확인했다. 오류 응답은 합성 Host 응답이며 설치된 VS Code UI 검증은 아니다.
- 이번 변경은 소스에 반영한 상태다. 기존 0.0.1146 설치본은 변경하지 않았다.

### 실제 함수 경로 추가 검증

0.0.1146 배포 커밋 `42cc7fb8894fc8c4dd898bf9343940e6aa335178`을 별도 폴더에
펼치고 이번 변경만 복사해 검증했다. 기존 SPEC/응답 정규화/schema의 진행 중 변경과
비공개 학습 소스는 제외했으며 해당 파일의 원본 해시가 유지된 것을 확인했다.

- 원본 함수 230줄·helper 88줄·caller 1줄을 실제 소스 수집 → 설정 공급자 →
  Qwen3.5-4B → Host 검증 → 페이지 저장 경로로 분석했다. 첫 입력 10,334토큰에
  문맥을 8K에서 16K로 확장했다. 번들 전과 수정 후 번들 양쪽에서 완료됐다.
  번들의 모델 호출 6회 모두 각 원본 줄의 누락이 없었다. 모델에 전달하기 전의
  캡처된 선언도 원본 전체 문자열과 일치했다.
- `enabled=true`의 `enabled`, `enabled=false`의 `disabled` 반환 예시가 모두 일치했다.
  두 저장 페이지는 모델을 추가 호출하지 않고 읽혔다. 소스 lease를 해제했고
  8K/16K 모델 프로세스 두 개의 종료를 실제 PID로 확인했다. 동시 소유한 watchdog은
  최대 1개였으며 검증 후 활성 프로세스는 0개였다.
- 실모델 검증 설정은 메모리 보존 20%였다. 수정 후 번들의 응답 직후 관측된 여유는
  31~40%, 종료 후에는 39%였다. 연속 관측값이 아니므로 전체 실행 중 최저치로 해석하지 않는다.
- 메모리 부족은 OS 관측만 18.75%로 대체해 Host가 `memory-pressure`를 반환하고
  모델 프로세스를 시작하지 않는 것을 확인했다. 실제 모델을 준비한 8K 상한 시험은
  추론 전에 `configured-context-limit`로 중단했고 해당 프로세스도 종료됐다.
- 별도 메모리 측정기를 주입한 공급자가 기존 풀의 다른 측정기를 재사용하는 문제를
  회귀 시험으로 재현하고 수정했다. 주입 측정기는 공급자별 컨트롤러에 묶으며,
  유휴 풀에는 경로와 정규화된 문맥 설정만 보존한다. telemetry callback/manager를
  풀의 옵션에 남기지 않는다.
- 관련 시험 111개와 번들 후 실행기/설정 시험 39개가 통과했다. 구형 실행기의 토큰화
  404 fallback, 잘못된 토큰화 결과의 추론 차단, 로드 후 메모리 부족, 128K 선택과 큰
  tokenizer 응답도 추가했다. 128K는 모의 실행기/메모리 시험이며 실제 모델 128K 실행은 아니다.
  샌드박스에서 소켓 실행기 시험 12개가 환경 오류로 종료돼, 같은 코드 전체를 필요한
  실행 권한으로 다시 실행한 결과가 111개 통과다. 작업 트리의 TypeScript 검사도 통과했다.

성능·해설 품질은 기능 검증 결과와 함께 기록한다. 동일 예제의 모델 생성 측정 합계는
번들 전 42.49초, 번들 후 88.11초였다. 초기 모델 준비/Host 작업은 제외하고 문맥 교체는
포함하며, 실행 시점의 다른 작업 부하를 통제하지 않아 번들 성능 비교로 사용하지 않는다.

전체 함수 요약이 true 분기의 반환만 구체적으로 설명하고 false 반환을 생략한 출력
한 건이 남아 있다. 두 실행의 요약 문장은 같았고 분기별 예시 결과는 정확했다.
이 검증으로 일반적인 해설 의미 품질까지 완료했다고 판단하지 않는다.

상세 수치·시험 로그 해시·검증한 소스 해시는
[추가 검증 결과](LOCAL_NARRATIVE_CONTEXT_VALIDATION.json)에 보존한다. 설치된 0.0.1146은
이번 검증에서도 변경하지 않았다.

요약 누락의 후속 평가는 [해설 품질 평가](LOCAL_NARRATIVE_QUALITY_ASSESSMENT.json)에
기록했다. 한 함수의 영어 출력에서 전체 요약 누락, 코드만 반복한 구문 설명,
가정 분류와 helper 의미 부여를 검토했다. 동일 모델·원문의 요약 전용 요청 한 번에서는
두 반환 결과를 언급했지만 helper를 항목 조회로 설명하는 표현은 남았다. 이 비교는
요청 범위·schema·경로 정보가 함께 달라진 탐색 진단이며 일반 품질 비율이나 단일 원인의
증명이 아니다. 평가 단계에서는 제품 코드를 변경하지 않았다.
